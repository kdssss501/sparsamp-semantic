# R055 双屏障合同差异诊断结果

## 材料护照

- 验证状态：`VERIFIED`。
- 数据文件：`outputs/R055_qwen_dual_barrier_trace.json`。
- 数据 SHA-256：`33f926626dc626b7ebf3d123a3cdec636e9d41e4af07bf79a4400ca5871c5047`。
- 模型与环境：Qwen2.5-1.5B-Instruct，同一 RTX 3060 Laptop GPU 上顺序执行 FP16 与 BF16。
- 冻结规模：20 个中英文 prompt，每个使用公开 seed 0，共 1,500 个 token step。
- checkpoint：逐 trial 原子保存；单 trial smoke 中断后能够续跑，重复完成命令不会重新执行 GPU trial。

## 原始结果

- FP16 参考合同精确复现：20/20 trial。
- BF16 修正集合与 R044 精确一致：20/20 trial。
- 有效 trial：20/20。
- 公开决策修正：30 次，占 1,500 步的 2.00%。
- `support_flip`：27 次，占全部修正的 90.00%。
- `mass_flip`：3 次，占全部修正的 10.00%。
- top-2 支持发生变化：65 步，其中 27 步改变公开决策。
- 支持相同但 counts 改变：168 步，其中 3 步改变公开决策。
- 同支持 counts TV：均值 0.005955，最大值 0.102676。

## 关键发现

观察：绝大多数实际修正不是由固定 top-2 支持内部的 CDF 边界轻微移动引起，而是由 top-2 候选集合发生变化引起。虽然 counts 变化比支持变化更常见，但只有很少 counts 变化真正跨越了公开采样点。

解释：R054 把两种机制混入一个全局边界半径。对 `support_flip` 而言，目标端合同已经更换候选，参考端 CDF 边界距离不再是正确风险变量；因此它需要异常大的半径，却仍产生 false-safe。

含义：R055 给出了分层证书的实证基础。支持变化应由参考端 rank-2/rank-3 稳定性屏障处理，固定支持内的质量迁移才应由 CDF 边界裕量处理。这是机制分解贡献，而不是参数扫描结果。

下一步：R056 已在读取细粒度阈值前冻结。偶数 prompt 分别校准支持 gap 与质量半径，奇数 prompt 只用参考端特征构造双屏障证书，并与同一 split 上的单边界基线比较。

## 结论边界

该结果来自一个物理 GPU 上的 FP16/BF16 数值环境，只能说明有限精度重放机制，不能表述为跨硬件认证。当前仅使用 seed 0；R056 即使通过，也必须扩展另外两个 seed 后才能形成稳定方法主张。R055 只建立错误机制分解，不单独证明双屏障证书有效。
