# R057 最近挑战者反事实屏幕研究合同

## 研究问题

R056 发现参考端 rank-2/rank-3 间隙较小时会频繁触发支持屏障，但多数位置即使第二名被第三名替换，公开 PRF 仍会选到同一参考 token。R057 检验能否把“支持不稳定”改写为更直接的“公开决策对最近支持替换是否敏感”，以减少不必要的参考 token 记录。

## 固定机制

对每个参考端 top-16 envelope，使用已经冻结的 rank-2/rank-3 gap 阈值判断第三名是否为可接受的最近挑战者。若可接受，则把原 top-2 的 rank-2 候选替换为 rank-3 候选；使用相同的量化 logits、整数质量分配、公开 PRF step、prompt 和 seed，重算反事实 token。仅当反事实 token 与参考 token 不同，支持屏幕才记录该位置。质量屏障仍按 R056 的同支持 CDF slack 规则构造。

该机制是“最近挑战者有限精度模型”下的充分决策不变性屏幕，不是对任意硬件或任意未观测候选替换的完整认证。因为 top-3 之外候选的排名不高于 rank-3，校准半径内的单次最近替换由 rank-3 表示；超出该模型的情形必须由独立重放实验检验。

## 开发与确认分离

- 开发材料：R055 seed-0 的 20 条轨迹。偶数 prompt 校准、奇数 prompt 仅作**回顾性开发检查**，不用于确认性结论，因为 R055/R056 已经暴露了其目标端结果。
- 确认材料：R044 中尚未被 R055 使用的 seed 1、seed 2。R058 生成其独立 FP16/BF16 轨迹后，固定使用本合同和 R057 开发阈值，不再查看确认集标签调参。

## 开发判据

报告 R057 屏幕相对 R056 的记录位置减少、回顾性 false-safe、完整轨迹负载和实际修正覆盖。只有在 seed-1/2 上达到至少 9/10 prompt（每 seed）精确覆盖，且负载低于 R056 的 63.02% 全轨迹基线，才能升级为确认性 pilot；否则该机制作为失败或边界发现保留。

## 报告边界

结果不声称对模型原始分布零偏差，不声称跨硬件认证，也不把回顾性 seed-0 数值当成确认性性能。所有输出必须引用输入 SHA-256、冻结阈值和配置签名。
