# R055 双屏障合同差异诊断研究合同

## 目的

R054 已预注册否定“单一 CDF 边界裕量足以构造低成本跨精度证书”。R055 不调整 R054 的 split 或阈值，而是检验一个新的分层机制：FP16/BF16 决策分歧是否能被拆分为候选支持变化与固定支持内的整数质量迁移。

若这种分层成立，后续方法将使用两道只依赖参考端信息的屏障：

- 支持屏障：参考端 rank-2 与 rank-3 的量化 logit bin 间隔；
- 质量屏障：公开整数采样值到 top-2 CDF 边界的方向裕量。

偶数 prompt 的目标端信息只用于校准两个阈值；奇数 prompt 的目标端信息只在证书冻结后用于留出评估。

## 输入与输出

输入固定为 `outputs/R044_qwen_replay_scale.json` 中的 20 个中英文 prompt、公开 seed 0、Qwen2.5-1.5B-Instruct、top-16 envelope、top-2 合同、`q=0.5`、`T=1.2`、`B=16`。

同一 RTX 3060 Laptop GPU 顺序加载 FP16 与 BF16 模型，不同时驻留两份模型。每个 trial 保存：参考端与目标端的 top-16 token IDs、量化 logit bins、top-2 counts、公开决策、支持重合、同支持 counts TV、边界裕量和归因标签。

输出是逐 trial 原子保存、可恢复的 JSON。配置签名或源文件 SHA-256 不一致时禁止合并。

## 算法伪代码

```text
输入：R044 参考轨迹，环境 E_ref=FP16、E_target=BF16
输出：逐步合同转移与 support/mass 归因

1. 加载 E_ref，一次只处理一个已保存参考轨迹：
   1.1 在每一步重新计算 top-16 envelope 和 top-2 整数合同；
   1.2 追加 R044 保存的参考 token；
   1.3 原子保存 trial；
   1.4 若合同或公开选择与 R044 不完全一致，停止目标端阶段。
2. 释放 E_ref，加载 E_target，沿同一保存轨迹重复采集。
3. 对每一步：
   3.1 若公开选择不变，标记 no_flip；
   3.2 若选择改变且 top-2 支持集合改变，标记 support_flip；
   3.3 若选择改变且支持相同但 counts 改变，标记 mass_flip；
   3.4 相同离散合同产生不同选择属于实现错误并立即失败。
4. 验证重新得到的 BF16 修正位置与 R044 完全一致。
5. 偶数 prompt 用于后续阈值校准，奇数 prompt 保持留出。
```

## 复杂度与终止条件

设轨迹总 token 数为 `T`，envelope 大小为 `K=16`。两个环境各执行 `T` 次模型前向，模型计算成本为 `O(T * C_model)`；合同记录和比较为 `O(TK)` 时间与 `O(TK)` 输出空间。算法有限终止，不涉及迭代优化或收敛近似。

有效性门禁如下：

- 20/20 FP16 trial 与 R044 的 token、top-2 支持和 counts 完全一致；
- 20/20 BF16 修正集合与 R044 完全一致；
- 所有 decision flip 都能唯一归因到 support flip 或 mass flip；
- 中断后恢复不得重算已完成 trial，配置变化必须硬失败。

R055 只是机制诊断，不以观察到的结果选择阈值。双屏障证书的阈值、留出覆盖率与成本将在独立的 R056 分析合同中预注册。
