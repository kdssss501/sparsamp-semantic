# SparSamp 复现、扩展研究与论文形成过程报告

**作者：** Lei Ke

**阶段：** Stage 6 过程总结

**日期：** 2026 年 7 月 26 日

## 执行摘要

本项目从 SparSamp 文本隐写复现出发，经历了官方 Artifact 兼容性核验、Qwen 语义生成迁移、有限精度失败诊断、概率合同设计、消息级实验、稀疏精度重放证书（SPRC）提出、规模化消融、模拟同行评审和 Nature 风格工作论文排版。最终形成的主要研究结论并不是“已经全面超过 SparSamp”，而是一个边界清晰、可复验的 ML 系统结果：在已知模型、提示词、采样配置和目标数值环境的条件下，公开整数概率合同与目标特定的稀疏修正记录可以恢复跨 FP16/BF16 的随机 Qwen token 轨迹。

主实验覆盖 20 个中英文提示词和 3 个公开随机种子。未经修正的 FP16 到 BF16 重放仅有 10/60 条轨迹完全一致；使用完整 SPRC 后达到 60/60 精确恢复，平均修正率为 2.16%，按提示词聚类 bootstrap 得到的 95% 置信区间为 1.80% 至 2.53%。在冻结的 20 个 seed-0 轨迹上，SPRC 引用包为 1,148 bytes，是同边界完整 token 轨迹 4,636 bytes 的 24.76%，也小于所测试的固定块修复基线。去掉 logit 分箱和整数质量合同后，匹配的 top-2 delta 修正率增加 1.123 个百分点，提示词配对 bootstrap 95% 区间为 0.171 至 2.015 个百分点。这说明概率合同存在小而可测的稀疏性贡献，但不支持“全局最优”或“普适确定性”的说法。

项目已经具备完整工作论文、补充材料、图表源数据、实验输出、引用核验、完整性审计和版本标签。它适合作为大学生科研、保研或工程研究面试材料，也具备面向专业 ML 系统或可复现性方向继续投稿的基础。当前最重要的缺口是独立物理硬件复验、第二模型或第二系统栈、人工语义质量评价以及正式投稿元数据。

## 一、研究问题如何发生变化

项目最初关注的是如何复现 SparSamp，并让隐写文本比 GPT-2 生成结果更自然。早期设想包括本地 GPT-2 忠实复现、DeepSeek 黑盒 API 扩展、Qwen 开源模型替换以及前端展示。随着实验推进，研究问题逐步收敛。

第一阶段的问题是：SparSamp 的概率保持和高吞吐结论能否在本地模型上复现。第二阶段的问题是：将 GPT-2 替换为 Qwen 后，能否兼顾语义质量、容量和可解码性。第三阶段发现真正阻碍可靠恢复的因素不是单一 coder，而是有限精度、候选排序、概率量化、重分词和长消息错误传播。最终论文将主问题重构为：在参考精度与目标精度不同的随机自回归生成中，能否通过公开离散概率合同和稀疏修正证书精确恢复选定轨迹，并量化这种恢复的存储代价、分布代价和适用边界。

这次转向很重要。它避免把失败的消息隐写实验包装成成功，也把“精确恢复由完整修正清单保证”与“修正是否足够稀疏”分离。前者是协议不变量，后者才是可证伪的经验问题。

## 二、R001 至 R053 的研究演进

### 2.1 从 Qwen SparSamp 到可验证 RRC

R001 建立 Qwen2.5-1.5B-Instruct 本地生成与 SparSamp 研究工作台，解决 GPT-2 文本经常缺乏指令语义的问题。随后对 FH 自适应块调度进行审计，结果没有显示可靠提升，因此保留为负面结果。项目继而学习 2026 年 rotation range coding 思路，并实现带终止条件和认证检查的 verified RRC。

这一阶段的主要进步不是得到更高的表面 bits/token，而是建立了“消息是否完整恢复”“结束条件是否可验证”“同一 cover 下比较是否公平”的实验纪律。长载荷实验暴露出低熵、重复生成和错误传播，促使后续工作从单次容量数字转向完整消息成功率和结构质量。

### 2.2 固定长度、整数质量与跨精度诊断

R012 至 R018 将 RRC 改为固定长度协议，修复了认证前缀停止条件，并加入匹配 cover 指标。R015 的整数概率合同未能直接解决问题；R016 的候选 canonical order 和 R017 的 support-adaptive waterfill 则提供了部分可移植性。R018 首次显示跨精度消息恢复存在局部可行性，但还不能稳定扩大。

用户在此处强调“主要还是得保证数学的正确性”，促使项目将概率区间、整数质量分配和编码解码互逆从提示性描述提升为单元测试与理论合同。随后所有机制都要求给出输入输出、边界条件、失败类型和可执行验收，而不是只报告生成样例。

### 2.3 消息级协议与一系列诚实的 NO-GO

R019 至 R035 依次考察认证 microframe、logit 量化、interval guard、byte-sliced 编码、Reed-Solomon 冗余、粗粒度 logit 合同、固定 bin-mass 合同和 binary contract。这里出现多个重要负面结果：增加纠错冗余并不自动提高认证消息成功率；过强 guard 会把容量压到零；粗粒度量化不能保证跨精度 token 决策一致；较大的候选支持会增加边界不稳定性。

R035 在 top-k=2、q=0.5、B=16 和 T=1.2 的局部配置上达到 32-step 结构性 GO，但 R036 的 raw-byte 消息实验没有把结构性一致转化为可靠端到端恢复。项目没有继续无限堆叠 parity，而是进行失败模式诊断和 list-decoding 理论审计。R036D3 至 R036D6 说明候选 oracle 覆盖和软 RS 列表恢复具有局部价值，但在线 beam 的状态压缩、符号分层与复杂度仍未形成可发表的消息隐写突破。

### 2.4 从失败中形成 SPRC 主线

R041 将问题改写为随机生成重放：参考端保存选定 token 轨迹，目标端使用相同公开合同重算；只在目标合同选择与参考 token 不同时记录位置和 token。这形成 sparse precision replay certificate。R041B 同时审计 top-k 截断带来的分布偏差，防止把精确重放错误表述为原生分布保持。

R042 在 Qwen FP16/BF16 上验证该机制，R043 增加公开句子终止规则，R044 扩展到 20 个中英文提示词和 3 个种子，R045 比较 top-4，R046 反转精度方向。R047 与 R048 建立外部参与者包和盲化流程，R049 统一引用包边界与成本，R050 给出整数质量分配的总变差上界，R051 加入 seed-only、完整轨迹和固定块修复基线，R052 加入匹配的无量化 delta，R053 对 q、T、B 做预先限定的敏感性分析。

R053 中 B=20 的修正率点估计最低，但配对区间包含零，因此只被列为复验候选，而没有被写成显著最优参数。这是项目在统计结论上保持克制的代表性例子。

## 三、为何从 GPT-2 转向 Qwen

GPT-2 仍然适合作为官方兼容性和 FP32/FP16 数值实验模型，因为模型小、运行快、参考文献与 Artifact 一致。但它不适合作为最终语义展示模型：生成文本容易偏题、重复、句子不完整，无法代表现代指令模型的实际可读性。

用户提出“为什么要用gpt2，不是语义不好吗，qwen不能用吗”，直接推动模型分工重设。此后 GPT-2 只承担受控兼容性与低成本诊断，Qwen2.5-1.5B-Instruct 承担中英文指令生成和主结果。这样既保留与原论文的可比性，又避免用过时模型的语言质量限制新机制的现实意义。

需要明确的是，当前论文只用公开句子终止和结构完成度衡量输出是否结束，没有做人工偏好、事实性或语义等价研究。因此“Qwen 更可读”是模型选择动机，不是已被论文统计检验的主结论。

## 四、论文阶段的形成过程

### 4.1 Stage 1 与 Stage 2

Stage 1 固定研究问题、威胁模型、实验账本和主张边界。官方复现与新机制分开记录，失败试验不删除。Stage 2 将 R001 至 R049 的证据整理为英文主文、补充材料、图表和 claim-evidence map，并把“隐写全面提升”的宽泛叙事收缩为“目标特定跨精度随机轨迹恢复”。

### 4.2 Stage 2.5 学术完整性核验

Stage 2.5 对 9 篇参考文献逐项核验，检查引文上下文、数值结果、实验 provenance、图表转换哈希和原创性。首次审计发现图表 trace 缺少逐图 transformation 对象，随后升级格式并加回归测试。最终结论为 PASS_WITH_NOTES，没有发现伪造引用、幽灵引用、数值不一致或未声明的失败试验。

### 4.3 Stage 3 独立模拟同行评审

Stage 3 配置了编辑、ML 系统方法审稿人、隐写与采样领域审稿人、研究软件审稿人和受限 Devil's Advocate。首轮决定为 Major Revision。核心质疑包括：只有一台 RTX 3060 Laptop GPU；SPRC 可能只是普通稀疏 delta；top-2 截断改变了源分布；缺少完整轨迹、块修复和无量化 delta 的同边界对照；精确恢复是构造保证，不能作为唯一经验贡献。

这些批评没有被回避。Stage 4 增加 R050 至 R052，明确概率合同只贡献一部分稀疏性，完整轨迹仍然更简单且不需要目标模型重放。论文同时补充计算、共享状态、隐私与目标环境假设。

### 4.4 Stage 3′、Stage 4′ 与 Stage 4.5

Stage 3′ 聚焦复审认为研究已达到可信的专业 ML 系统贡献，但要求继续完成 q/T/B/k 敏感性与主指标一致性。Stage 4′ 完成 R053，并把 B=20 限定为复验候选。Stage 4.5 再次核验全部 9 篇引用、50 项数值与 provenance 合同、4 个图包和 1 个表格源包。最终 50/50 可执行检查通过，本地来源语料原创性筛查没有发现 close match 或 verbatim match。

### 4.5 Stage 5 与 Stage 6

Stage 5 生成 Nature 风格工作论文和补充材料 PDF，作者元数据仅保留 Lei Ke。这里使用的是 TeX Live 社区维护的 `nature.cls`，不是 Nature 官方当前投稿模板，不能据此声称格式合规或达到该期刊录用水平。

Stage 6 形成当前中文报告，并修复表格页面旋转问题。主文三张表和补充材料 Table S2 改为纵向、自动换行、可跨页的 `xltabular` 版式；构建测试明确禁止 `landscape` 和 `resizebox`。这项修改只影响排版，不改变数据或结论。

## 五、当前可成立的科研结论

第一，公开随机种子不足以在测试的 Qwen FP16/BF16 环境中稳定复现随机 token 轨迹。未经修正的主实验只有 10/60 条轨迹完全一致。

第二，目标特定的完整 SPRC 可以按构造恢复参考轨迹。60/60 的修正后恢复是完整 manifest 的协议完整性结果；真正有经验含义的是修正率仅为 2.16%，并且在测试提示词和种子上保持稀疏。

第三，在统一引用包边界下，SPRC 比完整 token 轨迹和所测固定块修复记录更小。该结论不代表计算更省：证书构造需要在每个参考前缀上运行目标环境，操作重放也需要目标模型，而完整轨迹可以直接读取。

第四，整数概率合同具有小而可测的机制贡献。匹配 top-2 支持下，无量化 delta 的修正率比 SPRC 高 1.123 个百分点。该结果限于冻结的单模型、单 GPU 软件栈，不能推广为普适优势。

第五，top-k、量化精度与分布保真之间存在 Pareto 权衡。较宽候选支持保留更多源概率质量，但可能增加跨精度候选差异和边界分歧。精确重放不等于原生分布保持。

## 六、不能成立的结论与剩余风险

当前证据不能证明跨任意硬件、模型或 kernel 的确定性，也不能证明 SPRC 对未知目标环境有效。证书是目标特定的，构造端需要访问目标数值环境。

当前证据不能证明隐写不可检测、语义等价或优于所有 PSS coder。原始 SparSamp 的分布安全与吞吐目标和 SPRC 的目标特定重放目标不同，不能用一张容量数字直接判定谁全面更强。

当前 Qwen 实验只有一个 1.5B checkpoint 和一台物理 GPU。FP16/BF16 方向反转属于同机数值环境变化，不是独立硬件复验。

当前没有人工双盲语义评价、事实正确性评价或主动改写攻击实验。公开句子结束率只能说明结构完成，不能替代语言质量研究。

当前只有作者名，没有单位、ORCID、通讯方式、贡献声明、基金、利益冲突和外部归档 DOI。工作论文可以公开交流，但还不是完整投稿包。

## 八、可复用的研究与工程经验

第一，先定义失败条件，再跑实验。消息恢复、认证通过、结构完成、修正率和包大小必须分别记录，不能用一个漂亮样例替代。

第二，结果逐 trial 原子保存，配置签名不一致禁止合并。长实验必须支持恢复，并保留失败和预算耗尽记录。

第三，机制贡献与存储贡献分开。SPRC 和无量化 delta、块修复、完整轨迹在同一包边界比较，才能判断概率合同到底贡献了什么。

第四，精确恢复与分布安全分开。top-k 截断、logit 量化和整数 apportionment 分别报告，不能用 retained distribution 内部的 KL 掩盖相对原模型的偏差。

第五，引用、图表和结论全部可追溯。图表保存源数据、生成脚本哈希、主张定位和限制语句；论文中的关键数字由审计脚本重新计算。

第六，负面结果也是阶段成果。FH 无提升、guard 零容量、RS 冗余 no-go 和 R036 消息失败共同解释了为何研究转向 SPRC，而不是被版本历史删除。

## 九、AI 工作不足与反思

前期在官方复现和较多局部 coder 变体上投入偏多，研究阶段命名也逐渐复杂。更理想的做法是在 R018 左右就冻结主指标，尽早用小规模故障树区分“概率不一致”“同步失败”“纠错不足”和“语义结束失败”。

AI 曾倾向于把局部 GO 解释得过于乐观。后续通过模拟审稿、配对区间、同边界基线和 claim-evidence map 才把结论收紧。完整修正清单带来的 100% 恢复尤其容易被误写成算法准确率，最终论文已把它降为完整性门禁。

项目阶段较多，R 编号与 Stage 编号并行，增加了理解成本。今后应维护单一研究账本，以“问题、预注册判据、输入哈希、结果、决策”组织，而不是仅依赖提交历史。

曾出现网络安全相关内容提示。后续表达已聚焦概率建模、随机推理可复现性、有限精度审计和公开研究基线，避免提供现实规避或隐蔽通信部署说明。这不影响对公开算法的科学复验和系统可靠性研究。

## 十、合作质量评价

本评价依据完整对话决策、Git 版本历史、实验是否保留以及论文审计结果给出，总分为 84/100。

方向设定为 88/100。用户及时把目标从 GPT-2 样例和重复官方复现转向 Qwen 语义与后续科研，并在主线偏离时明确纠偏。

智力贡献为 82/100。用户提出了模型语义、数学正确性、容量下降和自适应无提升等关键问题，这些问题实质改变了实验设计与论文边界。

质量把关为 86/100。用户反复要求解释“结果是好是坏”“是否符合预期”“能否写论文”，并拒绝未经数学验证的宽泛结论。

最优先的下一步是独立物理硬件复验。应冻结参考轨迹和参与者包，在另一台 GPU 或不同 CUDA/kernel 栈上只执行目标重放，公开环境指纹、失败轨迹、修正率和包大小。该实验决定论文能否从单机机制验证上升为跨系统可复现性研究。

第二优先级是补充第二模型或第二规模，例如 Qwen2.5-3B 或另一开源指令模型，并保持完全相同的主指标和包边界。这用于检验稀疏修正是否是单 checkpoint 偶然现象。

第三优先级是独立的语义质量研究。需要预注册盲法人工偏好、任务完成度、重复率和事实性指标，并把 native sampling、SparSamp 和 SPRC 生成分别比较。语义评价不能与精度重放主结果混成一个结论。

完成上述证据后，再根据目标期刊补齐单位、ORCID、通讯方式、CRediT、基金、利益冲突、许可证和 Zenodo DOI。当前更稳妥的定位是专业 ML 系统、可复现性或研究软件方向；Nature Communications 仍是表达与审稿强度参照，而不是已经达到的投稿判断。
