# 从 SparSamp 到 BDS-RRC：完整科研历程

## 一、SparSamp：块编码隐写（起点）

### 问题
如何在 AI 生成的文本中隐藏秘密信息？

### 核心思想
语言模型每步输出一个概率分布（哪个词更可能），我们根据秘密信息选择哪个词。

### 具体例子
```
Prompt: "The quick brown"
模型输出 Top-8 个候选词（top_k=8，log2(8)=3 bits/步）:
  Rank 0: "fox"   (概率 0.8559)
  Rank 1: "dog"   (概率 0.0157)
  Rank 2: "cat"   (概率 0.0157)
  Rank 3: "bird"  (概率 0.0157)
  Rank 4: "rabbit"(概率 0.0095)
  Rank 5: "horse" (概率 0.0095)
  Rank 6: "deer"  (概率 0.0095)
  Rank 7: "bear"  (概率 0.0095)

秘密信息: "0100110111001010" (16 bits)

Step 1: 取前 3 bits "010" = 2，选 Rank 2 -> "cat"
Step 2: 取接下来 3 bits "011" = 3，选 Rank 3 -> "bird"
...继续直到 16 bits 全部编码

解码: 收到 "cat" -> 查到 Rank 2 -> "010"
      收到 "bird" -> 查到 Rank 3 -> "011"
      ...拼接恢复完整秘密
```

### 关键问题
块编码依赖 token 排序。如果 FP16 和 BF16 的排序不同，解码失败。

## 二、RRC：旋转区间编码（高效编码）

### 核心思想
不直接选词，而是维护一个数字区间。秘密信息是一个整数，区间不断收缩，最终区间中点就是秘密。

### 具体例子
```
初始: 区间 [0, 65536)，秘密 S = 19914
      (65536 = 2^16，称为整数质量 M)

Step 1: "The quick brown" -> 模型输出分布
  Token   概率      累积区间
  "fox"   0.8553   [0.0000, 0.8553)
  "dog"   0.0157   [0.8553, 0.8710)
  "cat"   0.0157   [0.8710, 0.8867)
  "bird"  0.0157   [0.8867, 0.9024)

随机偏移 O1 = 0.3712 (基于 HMAC 密钥)
S 在区间内旋转: S' = (19914 + 0.3712 x 65536) mod 65536 = 44231

S' = 44231，除以 65536 = 0.6750
0.6750 落在 "fox" 的区间 [0.0000, 0.8553)
-> 选 "fox"

区间收缩: [0, 65536) -> [0, 0.8553 x 65536) = [0, 56051)

Step 2: "The quick brown fox" -> 模型输出分布
  Token    概率      累积区间
  "jumps"  0.8939   [0.0000, 0.8939)
  "runs"   0.0205   [0.8939, 0.9144)

随机偏移 O2 = 0.6123
S' = (44231 + 0.6123 x 56051) mod 56051 = 37301

S' = 37301，除以 56051 = 0.6655
0.6655 落在 "jumps" 的区间 [0.0000, 0.8939)
-> 选 "jumps"

区间收缩: [0, 56051) -> [0, 0.8939 x 56051) = [0, 50100)

...继续直到区间宽度 < 1 (约 13-20 步)

最终区间中点 -> 逆向旋转 -> 恢复秘密 S = 19914
```

### 为什么 RRC 比块编码高效？
- 块编码：每步固定 3 bits（log2(8)）
- RRC：每步 -log2(P(token)) bits
  - 选 "fox" (P=0.8553): -log2(0.8553) = 0.23 bits
  - 选 "jumps" (P=0.8939): -log2(0.8939) = 0.16 bits
  - 但区间收缩快，总步数少

RRC 每步编码约 1-2 bits，利用了概率分布的信息论最优特性。

## 三、精度灾难：为什么 RRC 在跨精度下完全失效

### 核心问题
FP16 和 BF16 算出的概率分布不同，导致累积区间漂移。

### 具体例子（真实数据，来自 Qwen2.5-1.5B）
```
Prompt: "The quick brown"
Step 7 的分布:

FP16 (编码器):                     BF16 (解码器):
  Rank 0: token 374 (0.8273)         Rank 0: token 264 (0.5063)  <- 不同！
  Rank 1: token 264 (0.1047)         Rank 1: token 374 (0.4810)  <- 交换了！
  Rank 2: token 429 (0.0315)         Rank 2: token 429 (0.0117)

FP16 编码器选了 token 374 (Rank 0)
  cum_left = 0.0000, cum_right = 0.8273

BF16 解码器收到 token 374
  在 BF16 中 token 374 是 Rank 1
  cum_left = 0.5063, cum_right = 0.9873  <- 完全不同！

差异: |0.0000 - 0.5063| = 0.5063  <- 巨大的漂移！

区间宽度此时约 50000
中点误差 = 50000 x 0.5063 = 25315  <- 远超容差 0.5
```

### 误差累积（真实测量数据）
```
Step 0: diff = 0.0444  -> 误差 0.0444 x 65536 = 2910
Step 7: diff = 0.5063  -> 误差 0.5063 x 50000 = 25315  <- 排名交换！
Step 9: diff = 0.0144  -> 误差继续累积

最终: FP16 区间 [X, X+3], BF16 区间 [X-769, X-766]
      中点相差 769 -> 恢复的秘密完全不同 -> 0% 成功率
```

### 实验结果
```
标准 RRC 跨精度 (FP16->BF16): 0/60 (0%)
块编码跨精度:              0/30 (0%)
-> 所有现有方法都失败！
```

## 四、BDS：有界决策集（精度鲁棒性理论）

### 核心思想
不假设概率精确，而是建模概率的可能范围。

### 扰动模型
```
每个 logit bin 可以偏移 +/-Delta (Delta=1 对于相邻精度)

例如:
  Token A: bin = 0   -> 可能范围 [-1, 0, +1]
  Token B: bin = -1  -> 可能范围 [-2, -1, 0]
  Token C: bin = -8  -> 可能范围 [-9, -8, -7]
```

### 枚举所有可能的决策
```
对于 top-2 候选 (A, B)，枚举所有 bin 组合:
  (A=-1, B=-2) -> 整数质量分配 -> token A 被选
  (A=-1, B=-1) -> 整数质量分配 -> token A 或 B 可能被选
  (A=-1, B=0)  -> 整数质量分配 -> token B 被选
  (A=0, B=-2)  -> 整数质量分配 -> token A 被选
  (A=0, B=-1)  -> 整数质量分配 -> token A 被选
  (A=0, B=0)   -> 整数质量分配 -> token A 或 B 可能被选
  (A=+1, B=-2) -> 整数质量分配 -> token A 被选
  (A=+1, B=-1) -> 整数质量分配 -> token A 被选
  (A=+1, B=0)  -> 整数质量分配 -> token A 或 B 可能被选

决策集 D = {A, B}  ->  不是单元素 -> 需要记录此步
```

### 安全核心 (Safe Core)
```
如果决策集 D = {A} (只有 A)，则此步是安全的
-> 无论精度如何变化，都会选 A
-> 不需要记录此步
```

## 五、BDS-RRC 融合：修正证书（核心贡献）

### 关键洞察
BDS 告诉我们哪些 token 可能被选，但 RRC 需要的是确切的累积边界。

修正证书的思路：编码器记录每步的累积边界，解码器直接使用，不自行计算。

### 具体例子
```
Step 7: FP16 编码器选了 token 374 (Rank 0)
  证书记录: cl_int = 0, cr_int = 54211
  
  含义: cum_left = 0/65536 = 0.0000
        cum_right = 54211/65536 = 0.8273

BF16 解码器:
  不自算边界，直接用证书的 [0.0000, 0.8273]
  -> 区间收缩与编码器完全一致！
  -> 即使 token 374 在 BF16 中是 Rank 1，也不影响
```

### 证书格式
```
证书: tuple[(step, cl_int, cr_int), ...]
每项: 3 个 16-bit 整数 = 6 字节

96% 的步骤 cl_int = 0 (选第一个 token)
-> 压缩后: ~2.3 字节/步
-> 开销: 7-26x payload 大小
```

### 为什么证书是理论上最优的

定理 (Omega(T) 下界): 任何跨精度隐写协议必须传输 Omega(T) 比特辅助信息。

证明思路:
- 每步 delta_t > 0（FP16 和 BF16 的尾数长度不同，概率必然不同）
- 解码器需要解决不确定性 delta_t
- 至少需要 log2(M x delta_t) 比特/步
- 求和: Sigma log2(M x delta_t) >= T x log2(M x delta_min) = Omega(T)

我们的证书是 O(T) = 渐进最优！
